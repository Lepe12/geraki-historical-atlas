## 1. Πειραματική αποθήκευση: η αιτία είναι βαθύτερη από το κοινό JSON

Η αναπαραγωγή χρησιμοποίησε προσωρινό τοπικό bare repository με τα πραγματικά refs, detached checkout και μία συνθετική καταχώριση evidence. Δεν έγινε push ούτε άλλαξε το αρχικό repository.

| Έλεγχος | Αποτέλεσμα |
| --- | --- |
| Checkout βάθους 2 και `git pull --rebase origin main` | Exit 1· add/add σε πολλά ήδη υπάρχοντα αρχεία, περιλαμβανομένου `data/naboux_memory.json`. Σταμάτησε στην επανεφαρμογή του `ca1ce28f… Document safe NABOU Darwin workflow`. |
| Ίδιο branch με πλήρες διαθέσιμο ιστορικό | Exit 0, χωρίς συγκρούσεις. |
| Κανονική σύγκριση δέντρων main/experiment | Δεν έδειξε την ίδια σύγκρουση. Η διαφορετική συμπεριφορά της ρηχής ιστορίας είναι ουσιώδης. |

Στη ρηχή ιστορία η διαθέσιμη ιστορία δεν αρκεί για να επαναπαιχτούν μόνο οι σωστές αλλαγές του πειράματος. Μπορεί να επαναπαιχτεί το συνολικό δέντρο ενός παλιού commit σαν προσθήκη, συγκρουόμενο με αρχεία που υπάρχουν ήδη στο main. **Δεν είναι ασφαλές να λυθεί αυτό με τυφλό “ours/theirs” στο memory JSON.**

Η πλήρης ιστορία αφαιρεί αυτόν τον συγκεκριμένο αναπαραγόμενο μηχανισμό σύγκρουσης, αλλά **δεν απομονώνει το πείραμα** και δεν επιλύει τις ταυτόχρονες εγγραφές κοινής μνήμης. Χρειάζεται χωριστός προορισμός αποθήκευσης και ελεγχόμενος writer που μεταφέρει μόνο τα αποτελέσματα, όχι το πειραματικό ιστορικό κώδικα.

Δημόσιο αποδεικτικό πραγματικού βήματος: [greek job του 39164142122](https://github.com/Lepe12/geraki-historical-atlas/actions/runs/39164142122/job/117784512753), annotation `Preserve durable evidence in GitHub — Process completed with exit code 1`. Δεν ισχυριζόμαστε ότι η δημόσια annotation περιλαμβάνει το πλήρες μήνυμα conflict. Η συγκεκριμένη διαδρομή `add/add` αναπαράχθηκε τοπικά και συμφωνεί με το log που παρέθεσε ο χρήστης.

Ο αριθμός «46 evidence items» που ανέφερε ο χρήστης δεν επιβεβαιώθηκε ανεξάρτητα από το περιεχόμενο του artifact. Τα δημόσια στοιχεία επιβεβαιώνουν παραχθέντα artifacts και αποτυχία persistence· δεν δικαιολογούν χαρακτηρισμό όλων των lanes ως αποτυχημένη αναζήτηση.

## 3. Τα δέκα tasks δεν είναι ακόμη δέκα δεσμευμένες ιστορικές περιπτώσεις

Το baseline στέλνει `target=item.task`, κενές παραλλαγές/ημερομηνίες και `purpose=DARWIN_BASELINE|id|type`. Η πραγματική κανονικοποίηση κρατά και τις δέκα περιγραφές αυτούσιες ως target. Το parser αρχείο είναι ίδιο στο main και στο experimental branch, blob `db5a6b0eb10aaad38c6f4f3bd599a6787554dfb3`.

Πραγματικό πρώτο ερώτημα αναζήτησης που παράγεται:

> "Investigate Ioannis/John Kapsis (Καψής/Καψής variants), associated with Milos in the seventeenth century. Establish identity, chronology, titles, primary references and competing interpretations. Do not merge names without evidence." history

Αυτό δεν ισοδυναμεί με στοχευμένη αναζήτηση των ονομαστικών παραλλαγών Καψής/Ioannis Kapsis.

Έξι tasks είναι ανεπαρκώς ορισμένα: «μια πειρατική βάση» χωρίς βάση, «ένας χάρτης» χωρίς εικόνα/τίτλο/αναγνωριστικό, «αντικρουόμενες ημερομηνίες» χωρίς γεγονός και ημερομηνίες, «ένα ιστορικό πρόσωπο» χωρίς όνομα, «ένας στενά ορισμένος ισχυρισμός» χωρίς ισχυρισμό, «μια αμφισβητούμενη θέση» χωρίς τη θέση. Δεν επιτρέπεται να επινοηθούν αυτά τα στοιχεία για να προκύψει τεχνητό test pass.

Ο συντονιστής baseline ολοκληρώνεται επιτυχώς επειδή απέστειλε/παρακολούθησε τα runs και έγραψε τη σύνοψή του. Δεν απαιτεί επιτυχία των δέκα ούτε εφαρμόζει ιστορικό rubric. Το όνομα “Darwin baseline” δεν αποδεικνύει ότι εκτελέστηκε ο ορισμένος Darwin agent: το workflow καλεί το υπάρχον `pct-parallel-multi-agent.yml`.

## 5. HTTP400 και DB: ξεχωριστές αποδείξεις

Ο `verifyGithubOidc` ελέγχει ρητά `payload.ref === refs/heads/main`. Η διαδρομή `/events` μετατρέπει την εξαίρεση `wrong_ref` σε HTTP400. Σε τοπικό server με συνθετικό experimental-ref token αναπαράχθηκε ακριβώς `{error: wrong_ref}` πριν από το στάδιο κρυπτογραφικής επαλήθευσης. Δεν έγινε αίτημα στον παραγωγικό server ούτε παράκαμψη ελέγχου. Το event bus αποθηκεύει τοπικό event και μετατρέπει την αποτυχία remote delivery σε warning εκτός αν ζητηθεί `--require-remote`.

Αυτό εξηγεί συμβατή διαδρομή για το HTTP400 του πειράματος. Για οριστική ταύτιση κάθε πραγματικής απόκρισης χρειάζονται σώμα σφάλματος/receipt και έκδοση deployed server. Δεν πρέπει να ανοιχτεί αυθαίρετα η παραγωγική εξουσιοδότηση για όλα τα branches· προτιμάται τοπική καταγραφή experiment events ή ρητά απομονωμένη preview διαδρομή.

Η MariaDB έχει τεκμηριωμένο υφιστάμενο importer. Για τα συγκεκριμένα runs η ουρά `QUEUED_HOST_LOCAL_IMPORT` αποδεικνύει πρόθεση εισαγωγής, όχι ολοκλήρωσή της. Ο host-local έλεγχος `job RUN_ID`/storage audit παραμένει εκτός της διαθέσιμης σύνδεσης. Δεν συμπεραίνουμε ότι η DB χάλασε επειδή δεν έχουμε απόδειξη εισαγωγής εδώ.

## 6. Σειρά διορθώσεων και συγκεκριμένα κριτήρια επιτυχίας

1. **Απομόνωση πειραμάτων πριν από νέα baseline runs.** Ρητός τρόπος persistence σε όλα τα reusable jobs, χωρίς experiment writes σε main/κοινή μνήμη/παραγωγικό snapshot. Κριτήριο: ελεγχόμενη πειραματική εκτέλεση αφήνει το main και την κοινή μνήμη αμετάβλητα.
2. **Ασφαλής, ξεχωριστός publisher αποτελεσμάτων.** Επαρκές Git ιστορικό και writer που εισάγει μόνο διαδρομές evidence από artifacts, χωρίς rebase πειραματικού κώδικα στο main. Κοινή μνήμη με έναν serialized writer ή προσωρινά απενεργοποιημένη στα experiments. Κριτήριο: πραγματική παράλληλη αποθήκευση με αναγνώσιμα receipts/checksums και μηδενικά add/add· όχι force push.
3. **Έγκυρες, παγωμένες περιπτώσεις.** Ξεχωριστά target/question/aliases/date/material identifiers, ρητά αναμενόμενα τεκμήρια/κριτήρια και μία έκδοση κώδικα/μοντέλων/μνήμης. Ελλιπής περίπτωση χαρακτηρίζεται BLOCKED_INPUT. Κριτήριο: κανένα ολόκληρο essay ως quoted όνομα και κανένα επινοημένο missing input.
4. **Ενιαίες αποδείξεις κατάστασης ανά στάδιο.** Request → discovery/access → acquisition → extraction/analysis → event delivery → Git persistence → DB import → snapshot → historical evaluation. Κάθε στάδιο έχει run ID, έκδοση, status, αιτία και receipt. Η απουσία receipt παραμένει UNKNOWN, όχι success ή search failure.
5. **Έλεγχος πραγματικής διαθεσιμότητας παρόχων και μοντέλων.** Χωριστή διάγνωση ορίων/χρέωσης από ποιότητα αναζήτησης, συνολικό budget/concurrency για ολόκληρο cohort και ασφαλές preflight ρυθμίσεων μοντέλου. Το αν το cohort εξάντλησε τα όρια είναι υπόθεση που απαιτεί provider usage logs· δεν αποδεικνύεται μόνο από HTTP402/429.
6. **Μία πλήρης έγκυρη περίπτωση πρώτα, μετά οι υπόλοιπες.** Επιτυχής διέλευση όλων των τεχνικών σταδίων με ελεγχόμενα αποτελέσματα. Μετά τα δέκα συγκεκριμένα tasks υπό ίδιες συνθήκες και χωριστή επιστημονική βαθμολόγηση. Δεν δικαιολογείται άμεση τυφλή επανεκτέλεση όλου του cohort.
